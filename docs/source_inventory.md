# Source inventory (Phase 1)

> **All sources here are synthetic.** They are generated by `generator/` from a fixed seed to behave like real
> partner feeds. Real equivalents would contain minors' personal data, which is why none is used.
> Owners are fictional roles. Legal-basis entries are **design assumptions, not legal advice**.

Quality figures are *observed* rates from `quality.dq_summary` at the default configuration
(`config/generation.yaml`, seed 42). Re-run `make all` and query that model for current values.

## Known quality issues

Each issue links to a `defect_id` in `quality.dq_summary`; `quality.dq_defect_log` has the affected records and raw values.

### US_LEAGUE
- **Exact duplicates (double submit):** 1.5% of rows (192). `exact_duplicate`
- **Near-duplicates** (same person, league and season, new id and timestamp): about 1.0% (124). `near_duplicate`
- **Impossible DOB** (future date or age over 80): 0.5% (67). `impossible_dob`
- **Guardian email case or whitespace variants:** 8.0%. `guardian_email_case_whitespace`
- **Missing gender:** 3.0%, mapped to `U`. `missing_gender`
- **Missing photo consent:** 10%; **missing marketing opt-in:** 5%. Both stay NULL, never FALSE. `missing_photo_consent`, `missing_marketing_opt_in`
- **ZIP leading zero dropped:** half of the ZIPs that start with 0 (NJ, MA, CT). Restored in staging. `zip_leading_zero_dropped`
- **Mixed DOB formats** (`MM/DD/YYYY` and ISO) and **inconsistent labels** for gender and division: handled by `parse_flexible_date` and the seeds.
- **Not detectable in Phase 1:** name typos (4% of re-registrations), nickname use (3%), guardian email changed between seasons (6%), day/month-swapped DOB (1%). These need identity matching (Phase 2) or a second source.

### CA_CLUB
- **Birth year only**, so no full DOB and weaker identity signals. By design, `dob_precision = YEAR`.
- **Postal code not in standard form:** 15%. Normalized in staging. `postal_code_format`
- **Missing `consents` object:** 7%. Consent stays NULL. `missing_consents_object`
- **Null consent values inside the object:** photo 10%, marketing 5%. `null_photo_media`, `null_casl_marketing`
- **All-caps names:** 5%. `all_caps_names`
- **Pagination overlap duplicates:** 1%. `pagination_overlap_duplicate`
- **Bilingual free-text `program`:** mapped through `division_map`. `Atome` covers ages 5-7, so CA age-5 players map to `U8` where the US maps age 5 to `U6`.
- **Not detectable in Phase 1:** accents stripped (10% of accented names), birth year off by one (1.5%).

### INTL_FED
- **Header junk:** title row and blank row above the header on the DE and AT sheets; trailing `Total: N` rows on MX, GB, DE and PA. Dropped in staging and logged (`junk_*`).
- **UK DOBs as Excel date serials:** 20% of UK rows. Decoded in staging. `uk_dob_excel_serial`
- **Country spelled inconsistently:** 25% (`MEX` / `Mexico` / `MX`). `country_value_inconsistency`
- **Japan gives family name first;** handled by a sheet rule (`intl_family_name_first_countries`).
- **Full Name is one field,** so multi-word surnames split imperfectly (a small share of names; the exact count changes with the generated size).
- **Panama reissues Player ID every year,** so it cannot link a player across seasons.
- **Media consent blank:** 10%. `missing_media_consent`
- **Category labels do not line up with canonical divisions:** `U15` maps to `U14`, `Masters` to `ADULT_MIXED`. Noted in `division_map`.
- **Not detectable in Phase 1:** none of the rate-based defects; the two structural ones above (name order, reissued IDs) are rules, not data signals.

## Known but not onboarded

Two further sources are tracked in `dbt/seeds/source_registry.csv`, which feeds the data-trust KPIs "sources onboarded" and "sources known":
**school aggregates** (Source E, `Modelled` as a separate aggregate fact; see `docs/playbook/onboarding_log_SCHOOL_AGGREGATES.md`) and
**fan engagement** (Source D, `Modelled`: an accounts snapshot and an event stream under two contracts, linked to households only in the restricted
`linkage` schema, ADR-009; see `docs/playbook/onboarding_log_FAN_ENGAGEMENT.md`). The aggregate source is reported as a separate, non-deduplicated "reported
headcount" line and never mixed into resolved participants (methodology memo, section 8).

## Onboarding status definitions

`Discovery` (known, not yet profiled) -> `Profiling` (profiled in `dq_source_profile`) -> `Contracted` (a data contract is agreed; see `docs/playbook/onboard-a-source.md`) -> `Staged` (typed, standardized, flagged;
tests pass) -> `Modelled` (resolved into the participant model) -> `Production` (monitored, with owner sign-off).
All three sources ended Phase 1 at **Staged**. Identity resolution (Phase 2) resolves them into participants (`dim_participant`, `bridge_registration_participant`), which moves them to **Modelled**. None is `Production`: there is no monitoring, owner sign-off or persisted participant-ID registry (see ADR-004).
